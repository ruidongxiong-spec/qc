- [ ] **统一配置入口**：明确 CLI 的 `SCOPE_BASE_URL / SCOPE_MODEL / SCOPE_API_KEY` 与矩阵配置的 `base_url / model / api_key_env` 映射和优先级。示例只放密钥变量名；启动时检测占位 ID、缺失配置和不兼容选项，并给出可操作错误。
- [ ] **验证 URL 与协议兼容性**：检查不同服务的 `/chat/completions` 路径、认证头、模型名、temperature 和 JSON 模式。对于不支持 `response_format` 的模型，显式配置兼容方式并记录，不能静默改变实验设置。
- [ ] **完善响应解析**：覆盖空 choices、空 content、非 JSON、代码围栏、截断输出、错误字段与输出结构不合要求；区分模型输出错误和服务端错误，保留脱敏诊断。
- [ ] **完善超时和重试**：设置请求超时、有限次数退避、429 / 5xx 重试及 Retry-After 处理；401 / 403 / 错误模型 ID 快速失败。记录每次请求、等待及总耗时，避免重试失控或重复计费被遗漏。
- [ ] **完善 usage 与调用日志**：记录请求模型、返回模型、角色、请求 ID、状态、延迟、输入/输出 token、重试和错误类别；服务未提供 usage 时保留缺失标记，不填零。日志和异常不得包含密钥。
- [ ] **检查多角色配置**：明确 Planner / Executor / Verifier / Judge 是否共用模型，固定各角色提示词、温度、输出上限和版本；只有需要比较角色模型时再扩展配置，避免把不同设置混成同一实验。

- [ ] **补充必要测试**：模拟正常返回、401、429、5xx、超时、截断/非法 JSON、usage 缺失、配置优先级和密钥脱敏；在线验证单独记录日期、模型 ID 与结果。

完成标准：至少一个真实模型可稳定完成小规模端到端运行，配置可重用、错误可定位、调用记录可追溯；随后再扩展为模型矩阵。
